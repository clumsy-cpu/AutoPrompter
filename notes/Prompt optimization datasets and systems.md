# Separate selection from learning before tuning anything else

Every established prompt optimizer surveyed here does two things AutoPrompter does not. It takes labels from a source the optimizer LLM did not write (human benchmarks or programmatic verifiers). It also chooses its final prompt on data that is kept apart from the examples the optimizer reflects on, and it reports on a third test set that is never touched ([GEPA](https://arxiv.org/pdf/2507.19457), [MIPRO](https://arxiv.org/pdf/2406.11695), [TextGrad](https://arxiv.org/pdf/2406.07496), [PromptAgent](https://arxiv.org/pdf/2310.16427)). AutoPrompter's default dataset is written by the same Optimizer LLM from `task.description` alone and is scored on itself. Even the grounded fix has only 11 train and 5 holdout items, and the holdout plays no part in the loop. The loop is also built in a way that turns a train score of 1.0 into a lookup table. It shows the optimizer the expected outputs of failing items (`src/optimization_system.py:557`). It accepts every proposal without condition (`src/optimization_system.py:853`). It scores with a lenient `contains` metric that gives partial credit (`src/metrics.py:147`). Structurally, AutoPrompter is closest to OPRO's single trajectory and TextGrad's "evolve the best candidate". GEPA's own ablation shows that this greedy strategy earns about half the gain of Pareto selection and can fall below baseline ([GEPA Table 3](https://arxiv.org/pdf/2507.19457)). The changes most likely to raise holdout score, in order, are these: a three-way split with selection on validation, a guard against copying labels, a strict metric, larger sets, and several candidates per step. One caveat applies to all of them. The observed task asks for facts that live in files the target never sees, and no published method claims that prompt optimization can teach such facts ([knowledge-injection survey](https://arxiv.org/pdf/2502.10708)). Holdout gains there are capped until the facts reach the context.

## Published systems never let the optimizer author its own labels

Labels across the literature come from existing human-annotated benchmarks: BBH, GSM8K, Instruction Induction, HotpotQA, HoVer, Ethos, Liar and others ([APE](https://arxiv.org/abs/2211.01910), [OPRO](https://arxiv.org/abs/2309.03409), [ProTeGi](https://arxiv.org/pdf/2305.03495), [EvoPrompt](https://arxiv.org/pdf/2309.08532)). Programmatic verifiers are the other source, as in GEPA's IFBench feedback functions ([GEPA](https://arxiv.org/pdf/2507.19457)). The only "generated" labels in the surveyed systems are of two kinds. The first is **DSPy-style bootstrapped demonstrations**: a trace becomes a demo only if its output passes the metric against a gold label ([MIPRO](https://arxiv.org/pdf/2406.11695), [bootstrap.py](https://github.com/stanfordnlp/dspy/blob/bc8af7ed3d5ee0b892211e5c03274396442a413c/dspy/teleprompt/bootstrap.py#L95)). The second is **PromptWizard's synthetic few-shot examples**, which go inside the prompt as demos and are never the evaluation set ([PromptWizard](https://arxiv.org/pdf/2405.18369)). PromptWizard's README offers a no-data mode, but every benchmark result in its paper uses labelled training data ([README](https://github.com/microsoft/PromptWizard)). No surveyed paper builds a whole evaluation set from a task description, so AutoPrompter's default mode has no counterpart in the literature.

The grounded set is closer to accepted practice, and its build-time leak filters are stricter than anything documented in these systems. The filters are: verbatim in source, absent from the prompt, at least 4 characters, at most 3 words, and no digits. The nearest equivalent is OPRO's code, which rejects GSM8K instructions that contain digits or run over 500 characters ([opt_utils.py](https://github.com/google-deepmind/opro/blob/main/opro/optimization/opt_utils.py)). The weak points are size and selection role, not label quality. Table A sets the systems side by side. "Holdout in optimization" asks whether a set other than the reflection data drives candidate selection.

OPRO, which also optimizes on training data, reports training accuracy "often 5%-20% higher" than test accuracy and recommends "at least tens of samples" ([OPRO s5.4](https://arxiv.org/pdf/2309.03409)). That is an ordinary overfitting gap. A train-to-holdout gap of 1.0 against 0.40 is a different failure.

## Single-candidate greedy loops rank last in head-to-head ablations

The mechanics vary more than the datasets do, but one pattern holds in every ablation that tested it: **keeping several candidates beats evolving only the current best**. On Qwen3-8B, GEPA's ablation gives SelectBestCandidate +6.05 aggregate, BeamSearch(N=4) +5.11 and Pareto selection +12.44. Greedy fell to 30.44 on IFBench against a baseline of 36.90 ([GEPA Table 3](https://arxiv.org/pdf/2507.19457)). PromptAgent's matched-budget ablation ranks MC < Greedy < Beam < MCTS (0.635 / 0.697 / 0.698 / 0.754). The research note flags that column mapping as only partly verified ([PromptAgent Table 4](https://arxiv.org/pdf/2310.16427)). OPRO's sweep over candidates per step (1, 2, 4, 8, 16) found 8 best ([OPRO s5.3](https://arxiv.org/pdf/2309.03409)). ProTeGi's beam beat greedy on all three tasks shown, for example Liar F1 0.67 against 0.63 ([ProTeGi Table 2](https://arxiv.org/pdf/2305.03495)). AutoPrompter already has `generate_candidates` with five strategies and `evaluate_candidates_parallel` (`src/prompt_optimizer.py:200`, `src/optimization_system.py:282`). `run()` never calls them.

The second pattern is that **the acceptance gate sits on data the proposer did not learn from**. AdalFlow is the closest structural twin to AutoPrompter, since it is also a single-candidate hill climb. Each proposal must pass two checks before AdalFlow accepts it. It must beat the current score on a small error-heavy minibatch. It must then strictly beat the best score on the required validation set. Otherwise AdalFlow reverts and tries again, up to 5 times, and shows the failed proposals to the optimizer ([trainer.py](https://github.com/SylphAI-Inc/AdalFlow/blob/810de99d86191b3aa0c939aa6d6d1a21977555aa/adalflow/adalflow/optim/trainer/trainer.py#L2105)). Its paper reports that only **8.8-21.7% of proposals pass the full-validation gate** ([LLM-AutoDiff Table 3](https://arxiv.org/abs/2501.16673)). In other words, an ungated loop would accept mostly worse prompts. AutoPrompter sets `self.current_prompt = improved_prompt` every time the optimizer returns anything (`src/optimization_system.py:853`). Its significance test only labels which prompt counts as "best", and it runs on the same training scores. The task brief calls this test a bootstrap. The code describes a t-test with a bootstrap fallback (`src/optimization_system.py:432`).

The third pattern is **what the proposer sees**. MIPROv2's proposer gets a dataset summary, the program code, up to 3 demos and a random tip. It never sees scores or failures, so it cannot write row-level answers into an instruction ([grounded_proposer.py](https://github.com/stanfordnlp/dspy/blob/bc8af7ed3d5ee0b892211e5c03274396442a413c/dspy/propose/grounded_proposer.py#L370)). Even so, the MIPRO authors report that proposers tend "to overfit instructions to the few-shot examples provided in the meta-prompt" ([MIPRO](https://arxiv.org/abs/2406.11695)). GEPA reflects on a minibatch of 3 training examples per step, not the whole set ([GEPA App. E.4](https://arxiv.org/pdf/2507.19457)). AutoPrompter shows up to 3 failing items with their expected outputs and 2 partial items each iteration (`src/optimization_system.py:557`). It also stores 3 sample results with `expected` in the context history (`src/optimization_system.py:710`). Over a run on 11 items, the optimizer sees nearly every label.

## Ranked gaps and the changes that close them

The ranking is by expected effect on holdout score per unit of work. "Evidence-backed" means a cited system implements the mechanism and reports results with it. "Inference" means the mechanism is this report's proposal and no source tests it. No source measures the holdout effect of any of these changes on a task like AutoPrompter's, so every magnitude below is a direction, not a forecast.

**1. No validation-gated acceptance (evidence-backed).** The proposal replaces the current prompt without condition (`src/optimization_system.py:853`), and "best" is chosen on the same data the optimizer learned from. The change has three parts. Split the data into feedback (train), selection (val) and test. Accept a candidate only if it beats the incumbent on a small train minibatch and then on the full val set, and revert otherwise, as AdalFlow ([trainer.py](https://github.com/SylphAI-Inc/AdalFlow/blob/810de99d86191b3aa0c939aa6d6d1a21977555aa/adalflow/adalflow/optim/trainer/trainer.py#L2105)), TextGrad ([s3.3](https://arxiv.org/pdf/2406.07496)) and GEPA ([Alg. 1](https://arxiv.org/pdf/2507.19457)) do. Report test once, at the end. Run the existing significance test on val scores, not train scores. Expected effect: a lookup-table prompt raises train but not val, so it is never adopted. The selected prompt's holdout score should then match or exceed the current 0.40. The process cannot lift scores above what the candidates can reach, but it stops the regressions GEPA's greedy ablation and MAGE document.

**2. Labels flow into the optimizer's context (mechanism evidence-backed, guard is inference).** `_build_feedback_summary` prints `Expected format: {exp[:150]}` for failing items (`src/optimization_system.py:557`), and baseline history stores `expected` (`src/optimization_system.py:710`). The MIPRO authors document instructions overfitting to examples shown to the proposer ([MIPRO](https://arxiv.org/abs/2406.11695)). AGOPS reports that an unconstrained writer learns to "enforce the reference answer" ([AGOPS](https://arxiv.org/abs/2607.14105), preprint, snippet-level). The change has two parts. First, reject any candidate prompt that contains a normalized training label as a substring or n-gram. This generalizes OPRO's GSM8K no-digit rule ([opt_utils.py](https://github.com/google-deepmind/opro/blob/main/opro/optimization/opt_utils.py)) and is an inference: no source tests such a guard. Second, consider following GEPA's lead and showing only a 3-item minibatch per step. Expected effect: train scores drop back to an honest level. Holdout should not drop, because pasted answers earned nothing there, and it may rise because the optimizer must write transferable instructions instead.

**3. The `contains` metric rewards near-misses and guesses (literature practice evidence-backed; effect is inference).** The metric gives 1.0 when any number from the label appears anywhere in the answer, and 0.1-0.5 for token overlap (`src/metrics.py:147`). This is why "never say not documented, give a best guess" scored. Every surveyed system uses exact match, F1, accuracy or a programmatic verifier ([TextGrad](https://arxiv.org/pdf/2406.07496), [ProTeGi](https://arxiv.org/pdf/2305.03495), [MIPRO](https://arxiv.org/html/2406.11695)). The change: use `exact_match` or normalized-span match with no partial credit for grounded labels, and score a refusal as 0 explicitly. Following GEPA, also return feedback text that names the failure, such as "answer not found in output" ([GEPA Sec. 3](https://arxiv.org/pdf/2507.19457)). Expected effect: the reported holdout number may fall at first, because partial credit no longer inflates it. Gains that remain will be real. A preprint frames this as keeping "evidence of task quality independent of the optimized score" ([arXiv 2609.25848](https://arxiv.org/abs/2609.25848)).

**4. Sets are too small to measure anything (evidence-backed guidance; thresholds partly inference).** DSPy recommends about 10 examples only for BootstrapFewShot and 200+ for MIPROv2 "to prevent overfitting" ([optimizers.md](https://raw.githubusercontent.com/stanfordnlp/dspy/main/docs/docs/learn/optimization/optimizers.md)). GEPA used 111-150 train and 111-300 val ([GEPA App. E.1](https://arxiv.org/pdf/2507.19457)). A third-party GEPA re-implementation at N_train=30 regressed **28.4 points below the seed prompt** ([MAGE](https://arxiv.org/pdf/2607.11944), single-author preprint). With 5 holdout items, one question is worth 0.2 and the binomial standard error is about 0.2 (note-writer's arithmetic). The observed 0.27 → 0.40 averaged over 3 reps equals roughly two-thirds of one question, which is consistent with noise. The change: grow the grounded set to at least 30-50 val and test items each (an inference from the binomial arithmetic, not a cited threshold), and make reuse the default. Expected effect: no direct score change. Every other fix becomes measurable.

**5. One candidate per step and greedy search (evidence-backed, author-run ablations).** Wire `generate_candidates` and `evaluate_candidates_parallel` into `run()`. Sample 4-8 candidates per step, as OPRO found 8 best ([OPRO s5.3](https://arxiv.org/pdf/2309.03409)). Score them on a train minibatch, gate the leaders on val, and keep a small pool so parents can be chosen by per-instance wins, following GEPA's Pareto selection ([GEPA Alg. 2](https://arxiv.org/pdf/2507.19457)). This replaces the 5-iteration stagnation trigger, which GEPA's results suggest is weaker than structural diversity. Expected effect: GEPA reports Pareto selection roughly doubles greedy's gain (+12.44 vs +6.05). Those are author-run numbers on large datasets, and how well they transfer to n=11 is unknown.

**6. No separate channel for demonstrations (evidence-backed).** Wan et al. found that optimized exemplars generalize with smaller validation-test gaps than optimized instructions, and that combining the two works best ([Wan et al.](https://arxiv.org/pdf/2406.15708v2)). MIPRO found that demos alone (Bootstrap RS) beat the best instruction-only optimizer in all but one case ([MIPRO s6](https://arxiv.org/abs/2406.11695)). The change: add an explicit few-shot slot, capped at 4 bootstrapped and 4 labelled demos as in DSPy ([code](https://github.com/stanfordnlp/dspy/blob/bc8af7ed3d5ee0b892211e5c03274396442a413c/dspy/teleprompt/mipro_optimizer_v2.py#L53)), and select its contents on val. Keep the instruction text free of answers (gap 2). Expected effect: the optimizer's urge to paste answers gets a bounded, val-checked outlet. Format and style transfer to holdout. The facts in the demos do not.

**7. Untested sections get deleted (inference).** No surveyed paper guards against this. GEPA treats shorter prompts as a benefit ([GEPA Obs. 4](https://arxiv.org/pdf/2507.19457)), which points the other way. The change: either score those sections (add holdout items or constraints that exercise them, as in IFBench-style verifiers) or mark them read-only and reject candidates that change them. Expected effect on this holdout: neutral. It protects behaviour the metric does not see.

**8. The task asks for facts the target cannot see (inference with indirect support).** A survey classes prompt optimization as "fundamentally limited by the knowledge already present in the model" ([arXiv 2502.10708](https://arxiv.org/pdf/2502.10708)). AGOPS finds that reference answers carry missing information, which optimizers then pull into prompts ([AGOPS](https://arxiv.org/abs/2607.14105)). The change: give the target the relevant source text through retrieval or context, or switch the objective to behaviour the model can learn, such as format or abstaining when unsure. Expected effect: probably the largest single lever on holdout for this task, because it removes the ceiling that gaps 1-7 only expose. This rests on the note-writers' inference. No controlled study was found.

**9. The default dataset has no independent labels (evidence-backed by absence).** No surveyed system evaluates on optimizer-written labels. The change: make the grounded build and `reuse_dataset: true` the default path, or require a user-supplied dataset. Expected effect: removes circular scoring. The size of the effect is unknown.

## Evidence quality is mostly author-reported

Peer-reviewed venues, per the notes: APE (ICLR 2023), OPRO, EvoPrompt and PromptAgent (ICLR 2024; PromptAgent's venue is per its README), ProTeGi (EMNLP 2023), PromptWizard (Findings of ACL 2025; the notes read arXiv v2, whose numbers may differ from the camera-ready version) ([venues](https://preview.aclanthology.org/new-sigs/2025.findings-acl.1025/)), and Wan et al. (NeurIPS 2024). **The notes disagree on several venues.** Three notes give GEPA as an ICLR 2026 oral based on its PDF header, while the overfitting note marks that status "unknown". The overfitting note tags MIPROv2 as EMNLP 2024, while the DSPy note treats it as an unverified preprint. TextGrad's Nature 2025 listing comes from its README; the Nature page was not opened, and its numbers may differ from arXiv v1. The DSPy paper's ICLR 2024 status was not verified.

Third-party or cross-run evidence is thin. GEPA's paper re-ran MIPROv2 and TextGrad, but GEPA's authors ran those comparisons themselves. AdalFlow's paper replicated TextGrad on ObjectCount (95.25 val vs 84.5 test) as a competitor. PromptWizard's EvoPrompt cost figure (5,000 calls) is PromptWizard's own formula, and its BBH baselines are copied from EvoPrompt's table ([PromptWizard](https://arxiv.org/pdf/2405.18369)). The only independent re-implementations found are MAGE ([2607.11944](https://arxiv.org/pdf/2607.11944)) and "Why Prompt Optimization Works, and Why It Sometimes Doesn't" ([2605.26655](https://www.alphaxiv.org/abs/2605.26655.md)). The second analyses MIPROv2, TextGrad and GEPA across 11 benchmarks and finds that only 2 of 60 tests survive FDR correction. Both are preprints, and the second was read only through a secondary summary. Another preprint found that OPRO "shows limited effectiveness in small-scale LLMs" ([2405.10276](https://arxiv.org/abs/2405.10276)).

Preprint-only: AdalFlow's LLM-AutoDiff, MAGE, AGOPS, and the reward-hacking preprint 2609.25848. Code, README or docs only: SIMBA (no paper read), COPRO (no gains found), AdalFlow's "better performance than DsPy" ([README](https://github.com/SylphAI-Inc/AdalFlow/blob/810de99d86191b3aa0c939aa6d6d1a21977555aa/README.md#L259)), PromptWizard's no-data mode and its "20-30 minutes", DSPy's data-size tiers, Opik's 70-80/20-30 split advice ([Opik](https://www.comet.com/docs/opik/development/optimization-runs/optimization/define_datasets.md)), and LangChain's note that some optimizer configurations overfit ([LangChain blog](https://www.langchain.com/blog/exploring-prompt-optimization)).

The notes also record other points of disagreement or uncertainty. MIPROv2's default split is 80% val / 20% train. A first WebFetch summary reversed this, and the raw code check corrected it ([code](https://raw.githubusercontent.com/stanfordnlp/dspy/main/dspy/teleprompt/mipro_optimizer_v2.py)). ProTeGi's released code has bandit-style arguments, but a summary reported no bandit implementation, so this remains unresolved. ProTeGi's repo default UCB constant is c=1.0, while the paper uses 2.0. The overfitting note cites OPRO's 5-20% gap through a HackerNoon summary, while the OPRO note reads the same claim from the PDF directly. The PDF reading should be preferred. GEPA's Fig. 16 generalization-gap numbers were not extracted, so the claim of a "lower generalization gap" is qualitative here. No source measures how often labels are copied into prompts, and no source tests an n-gram leakage filter.

## Conclusion

AutoPrompter's result is not an exotic failure. It is what happens when the separation that every credible method enforces is missing. In this loop, the data the optimizer reflects on, the data that decides acceptance, and the data used to report success are the same 11 items, and the expected answers are printed into the optimizer's context. Under those conditions a capable optimizer will memorize. AutoPrompter's distinctive assets point to a better role for it. Grounded labels with verbatim and absent-from-prompt filters are stricter than anything documented in these systems, and the significance test is something no surveyed loop runs. Those assets are worth most once they sit on a held-out validation set.

The evidence also argues for humility about the whole category. Headline gains are almost all author-run. The few independent studies find gains that often fail to transfer, or regressions on small training sets, and a fixed, well-written prompt sometimes wins. So the first deliverable is a trustworthy measuring instrument: a three-way split, strict metric, label guard, and 30+ val/test items. A better proposer comes after. For the current documentation-QA task specifically, the evidence suggests the ceiling is set by missing context, not by prompt wording. A clean instrument would show that quickly, and could save iterations spent optimizing toward an unreachable target.
